# zipnative v0.8.2

<!-- GitHub Release title: v0.8.2 — conformance pass on 0.8.1 -->

_Released 2026-09-01_

A conformance pass on 0.8.1 — a forensic follow-up review of the previous release: the reported `docs:serve` 404s root-caused to a URL shape (not to missing files), one real spec-conformance fix in the incremental writer, honest disclosure of a behavioral change 0.8.1 had mislabelled "Breaking: None", and a factuality sweep across the entire documentation surface. **100% backward-compatible with v0.8.1** for valid inputs; deterministic bytes unchanged. Zero runtime dependencies, 350+ tests, 91.7% coverage. Tagged in git; not published to npm.

## Highlights

- **The 404s were a URL-shape bug, and they are gone.** `npx serve`'s default `cleanUrls` redirects `/guides/index.html` down to `/guides` *without* a trailing slash, which rebases every relative URL to `/` — `guide.css` 404'd (the unstyled hub), and every hub link (use-cases included) 404'd. All hub links are now directory-form (`guides/`, `playgrounds/`, `./`), the shape pdfnative uses; canonicals, sitemap and JSON-LD follow. Verified end-to-end against a live `npx serve`.
- **APPNOTE §4.5.3 conformance** — a local header's Zip64 extra must carry both sizes; the 0.8.1 append path emitted only the overflowed one. Fixed and unit-tested (`lfhZip64Fields`), closing the one review finding that had shipped without its regression test.
- **Documentation is now factual end-to-end**: interop numbers, test and coverage metrics, rule counts (verify-docs stands at 21), tier claims, and the README's missing 0.8 story (frozen `err.code` vocabulary, playgrounds, use cases) — every checkable claim re-verified against the tree.

## Security

- **No parser/writer posture change.** The one message-level change is an honesty fix: refusing a Windows reserved device name now says CWE-67 instead of claiming a zip-slip.
- **Disclosure (behavioral change shipped in 0.8.1, now documented):** default extraction refuses entries named `CON`, `NUL`, `COM1`…`LPT9` (with or without extension) and names collapsing to nothing — a POSIX-authored archive containing `aux.h` throws by default on every platform. Opt out with `rejectTraversal: false` (such entries are skipped, never emitted).

## Fixed

- **fix(docs):** directory-form navigation everywhere (hubs, canonicals, sitemap, JSON-LD) — closes the `docs:serve` 404s and the unstyled guides hub.
- **fix(parser):** `lfhZip64Fields` — APPNOTE-conformant local-header Zip64 extra (both sizes present), unit-tested with synthetic ≥ 4 GiB sizes.
- **fix(docs):** the inspector playground decodes the archive comment (`Uint8Array`, not string).
- **fix(core):** set-only UTF-8 flag — `planForCopy` never *clears* bit 11 (ASCII is valid UTF-8; clearing contradicted the determinism contract).
- **fix(ci):** the docs workflow builds before verifying, making the `playground-bundle` byte comparison real in CI.
- **docs(meta):** the factuality sweep — measured metrics, corrected historical claims, playground discoverability, README badges. See [CHANGELOG.md](../CHANGELOG.md#082---2026-09-01) for the per-line record.

## Install

Not published to npm — pre-1.0 versions are git tags (`git checkout v0.8.2`); the first npm publication is v1.0.0.

## Upgrade

No breaking changes in 0.8.2 itself. Drop-in replacement for v0.8.1. If your inputs include POSIX archives carrying Windows-reserved names (`aux.h`, `con.log`, …), default extraction now refuses them — pass `rejectTraversal: false` to skip instead.

## Known limitations

Unchanged from 0.8.1 (store+bit3 / encrypted+bit3 forward reads; Zip64 streaming for `addStream` > 4 GiB; zipnative.dev DNS).

## Downstream integration notes

Static hosts that never rewrite URLs (GitHub Pages included) were never affected by the 404s — the directory-form links are simply the canonical shape everywhere now.
