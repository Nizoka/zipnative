# zipnative v0.8.2

**Conformance pass on 0.8.1** — a forensic follow-up review of the
previous release: the reported `docs:serve` 404s root-caused to a URL
shape (not to missing files), one real spec-conformance fix in the
incremental writer, honest disclosure of a behavioral change 0.8.1 had
mislabelled "Breaking: None", and a factuality sweep across the entire
documentation surface.

## Highlights

- **The 404s were a URL-shape bug, and they are gone.** `npx serve`'s
  default `cleanUrls` redirects `/guides/index.html` down to `/guides`
  *without* a trailing slash, which rebases every relative URL to `/` —
  `guide.css` 404'd (the unstyled hub), and every hub link (use-cases
  included) 404'd. All hub links are now directory-form (`guides/`,
  `playgrounds/`, `./`), the shape pdfnative uses; canonicals, sitemap
  and JSON-LD follow. Verified end-to-end against a live `npx serve`.
- **APPNOTE §4.5.3 conformance** — a local header's Zip64 extra must
  carry both sizes; the 0.8.1 append path emitted only the overflowed
  one. Fixed and unit-tested (`lfhZip64Fields`), closing the one review
  finding that had shipped without its regression test.
- **Documentation is now factual end-to-end**: interop numbers, test
  and coverage metrics, rule counts (verify-docs stands at 21), tier
  claims, and the README's missing 0.8 story (frozen `err.code`
  vocabulary, playgrounds, use cases) — every checkable claim
  re-verified against the tree.

## Security

- No parser/writer posture change. The one message-level change is an
  honesty fix: refusing a Windows reserved device name now says CWE-67
  instead of claiming a zip-slip.
- **Disclosure (behavioral change shipped in 0.8.1, now documented)**:
  default extraction refuses entries named `CON`, `NUL`, `COM1`…`LPT9`
  (with or without extension) and names collapsing to nothing — a
  POSIX-authored archive containing `aux.h` throws by default on every
  platform. Opt out with `rejectTraversal: false` (such entries are
  skipped, never emitted).

## Breaking Changes

None in 0.8.2 itself.

## Fixed / Changed

See [CHANGELOG.md](../CHANGELOG.md#082---2026-09-01) — directory-form
navigation, `lfhZip64Fields`, inspector comment decoding, set-only
UTF-8 flag, the CI build step that makes the `playground-bundle` byte
comparison real, and the factuality sweep.

## Known limitations

Unchanged from 0.8.1 (store+bit3 / encrypted+bit3 forward reads; Zip64
streaming for `addStream` > 4 GiB; zipnative.dev DNS).

## Downstream integration notes

Static hosts that never rewrite URLs (GitHub Pages included) were never
affected by the 404s — the directory-form links are simply the
canonical shape everywhere now.
