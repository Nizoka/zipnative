# zipnative v0.2.0

<!-- GitHub Release title: v0.2.0 — deterministic write & streaming -->

_Released 2026-09-01_

Milestone M2 — deterministic write and streaming. `createZip()` gains a buffered and a streaming consumer of one shared segment generator (byte-identical by construction), backed by a real pure-TypeScript raw DEFLATE encoder that pins the determinism contract: identical inputs give identical SHA-256 on every runtime. **100% backward-compatible with v0.1.0**; from this release onward the `deterministic: true` output bytes are a frozen contract — changing them is semver-major. Zero runtime dependencies. Tagged in git; not published to npm.

## Highlights

- **`createZip()`** with `toBytes()` (sync) and `stream()` (bounded memory) — both consume one shared segment generator, so output is byte-identical by construction.
- **A pure-TypeScript raw DEFLATE encoder** — the determinism pin: `compression: { deterministic: true }` gives identical SHA-256 for identical inputs on every runtime. Within 5% of zlib -6; 25–55 MB/s.
- **The determinism contract is written down** in `docs/guides/determinism.md` *before* anyone depends on it, and frozen by golden SHA-256 tests.
- **The interop conformance gate is blocking in both directions**: foreign extractors (Expand-Archive, bsdtar, unzip, 7z, python zipfile, jar) validate and byte-compare zipnative's archive matrix, including streamed data-descriptor entries and a 66 000-entry Zip64 archive.

## Security

- **feat(security):** the writer never emits traversal-capable names — `add()` rejects `..` segments, absolute paths, drive letters and backslashes outright.
- **feat(security):** reader overlap defence reworked to O(log n) per read with the same guarantee for every entry actually read (duplicate header offsets rejected; `validate: 'eager'` checks every entry up front).

## Added

- **feat(core):** `createZip` / `ZipWriter` (`add`, `addDirectory`, `addStream`, `setComment`, `toBytes`, `stream`), Zip64 auto-promotion, canonical or insertion entry ordering, per-entry compression options.
- **feat(codecs):** deflate compression facade with a `level`-aware injection point (`setDeflateImpl`), node:zlib tier, and the pure-TS tier.
- **feat(bench):** scenario benchmarks vs fflate/jszip/adm-zip + committed `bench/RESULTS.md`.
- **feat(docs):** recipes `deterministic-build` and `create-streaming`.

## Changed

- **chore(codecs):** `initNodeZipCodecs()` now initializes both directions (inflate + deflate).

## Install

Not published to npm — pre-1.0 versions are git tags (`git checkout v0.2.0`); the first npm publication is v1.0.0.

## Upgrade

No breaking changes. Drop-in replacement for v0.1.0.

## Downstream integration notes

Known limitation worth noting for future CLI design: `addStream` entries beyond 4 GiB throw `ZipUnsupportedError('zip64-streaming')` — the CLI's large-file path should buffer or split until Zip64 streaming lands (post-M4).
