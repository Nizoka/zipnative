# zipnative v0.2.0

Milestone **M2 — deterministic write + streaming**.

## Highlights

- `createZip()` with `toBytes()` (sync) and `stream()` (bounded memory) —
  both consume one shared segment generator, so output is byte-identical
  by construction.
- A real **pure-TypeScript raw DEFLATE encoder** — the determinism pin:
  `compression: { deterministic: true }` gives identical SHA-256 for
  identical inputs on every runtime. Within 5% of zlib -6; 25–55 MB/s.
- The **determinism contract** is written down in `docs/determinism.md`
  *before* anyone depends on it, and frozen by golden SHA-256 tests.
- The interop conformance gate is now **blocking in both directions**:
  foreign extractors (Expand-Archive, bsdtar, unzip, 7z, python zipfile,
  jar) validate and byte-compare zipnative's archive matrix, including
  streamed data-descriptor entries and a 66 000-entry Zip64 archive.

## Security

- The writer never emits traversal-capable names: `add()` rejects `..`
  segments, absolute paths, drive letters and backslashes outright.
- Reader overlap defence reworked to O(log n) per read with the same
  guarantee for every entry actually read (duplicate header offsets
  rejected; `validate: 'eager'` checks every entry up front).

## Breaking Changes

None. (Pre-1.0: the `deterministic: true` output bytes are now a frozen
contract — from this release onward, changing them is semver-major.)

## Added

- `createZip` / `ZipWriter` (`add`, `addDirectory`, `addStream`,
  `setComment`, `toBytes`, `stream`), Zip64 auto-promotion, canonical or
  insertion entry ordering, per-entry compression options.
- Deflate compression facade with a `level`-aware injection point
  (`setDeflateImpl`), node:zlib tier, and the pure-TS tier.
- Scenario benchmarks vs fflate/jszip/adm-zip + committed `bench/RESULTS.md`.
- Recipes: `deterministic-build`, `create-streaming`.

## Changed

- `initNodeZipCodecs()` now initializes both directions (inflate + deflate).

## Fixed

None.

## Downstream integration notes

None (satellite packages do not exist yet). Known limitation worth noting
for future CLI design: `addStream` entries beyond 4 GiB throw
`ZipUnsupportedError('zip64-streaming')` — the CLI's large-file path
should buffer or split until Zip64 streaming lands (post-M4).
