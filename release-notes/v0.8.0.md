# zipnative v0.8.0

**Error-code stability + the pdfnative docs charter** — the first wave of
the API-freeze band (0.8 → 0.9). No archive-byte changes; the API is
additive.

## Highlights

- **Every thrown error now carries a stable machine-readable code.**
  `err.code` comes from a closed 39-code union (`ZIP_EOCD_NOT_FOUND`,
  `ZIP_PATH_TRAVERSAL`, `ZIP_CRC_MISMATCH`, …) with per-cause
  granularity across ~110 throw sites. Agents and wrappers branch on the
  code — never on message text. The vocabulary is **frozen from 0.8.0**
  (removal/renaming is semver-major), registered in
  `docs/data/errors.json`, documented in the new errors guide, and
  policed by the 20th verify-docs rule, `error-parity`.
- **`createInflator()` is public.** The freeze decision left open since
  0.6 is resolved: the resumable raw-deflate decoder — the only inflate
  in the ecosystem reporting exact `bytesConsumed` — ships as API,
  surface unchanged and already differentially fuzzed since two
  releases.
- **The docs site now carries the exact pdfnative charter**: same
  tokens, same layout rhythm, same guide chrome, Prism highlighting,
  a proper architecture diagram, and honest comparison/benchmark
  sections with measured numbers.

## Security

- **No archive-parsing behavior change** — the security posture is
  identical to 0.7.0.
- The error codes *strengthen* security tooling: every refusal
  (traversal, overlap, Zip64 spoofing, limits) is now dispatchable
  without string matching, and the security guide's threat table links
  each CWE row to its code.
- One thrown-class widening, called out deliberately: `strict: true`
  escalation now throws a typed `ZipError` (code
  `ZIP_STRICT_DIAGNOSTIC`) instead of a bare `Error` — closing the one
  hole in the "typed errors" promise.

## Breaking Changes

None at runtime. Error constructor signatures are now code-first — a
construction-only change (constructing zipnative errors externally has
no use case pre-1.0); `catch` sites are unaffected.

## Added

- `ZipErrorCode` + six per-class sub-unions + `ZipUnsupportedFeature`
  (all exported); `docs/data/errors.json`; `docs/guides/errors.md`;
  the `error-parity` rule.
- `createInflator` / `Inflator`, `activeDeflateTier()` / `DeflateTier`,
  `FLAG_ENCRYPTED` / `FLAG_DATA_DESCRIPTOR` / `FLAG_STRONG_ENCRYPTION` /
  `FLAG_UTF8`; `StreamOptions` from `zipnative/worker`;
  `"./worker/zip-worker.js"` in the exports map.
- Docs: full pdfnative-charter retheme (landing + guide chrome +
  `assets/architecture.svg` + Prism with SRI), api.json covering the
  `./worker` subpath (69 exports).

## Changed

- `_spawn` (an internal test seam) removed from the public
  `ParallelZipOptions`; dead layer barrels deleted;
  `ZipLimitError.limit` types as `keyof ZipLimits`.

## Fixed

None engine-side.

## Known limitations

- store+bit3, encrypted+bit3 and custom-codec+bit3 remain refused in
  forward reading — structurally undelimitable without the central
  directory.
- Zip64 streaming (`addStream` > 4 GiB) remains a typed refusal; the
  per-entry opt-in design lands with the 0.9 decision record.
- zipnative.dev DNS/CNAME activation is a deployment step, not a repo
  artefact.

## Downstream integration notes

The future CLI/MCP satellites should consume `docs/data/errors.json` as
their error-contract source of truth — the `--json` envelope can carry
`err.code` verbatim from 0.8.0 onward.
