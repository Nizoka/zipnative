# zipnative v0.8.1

**Docs finish + a full multi-agent code review.** A patch release: no API
changes, no archive-byte change for valid inputs, the deterministic
encoder contract untouched — thirteen verified correctness/security/
resource fixes and the documentation the 0.8 site was still missing.

## Highlights

- **A three-agent code review, all findings fixed.** Two reviewers swept
  the parsing/modification stack and the codecs/write/worker stack; an
  adversarial verifier confirmed every one of the 13 findings (6
  reproduced at runtime) and vetted each fix against the project
  doctrine and the frozen determinism contract. Twelve of the thirteen
  ship with a regression test; B7 (dispatch-time payload slicing, an
  allocation-timing change with no observable behavior) is verified by
  inspection.
- **Interactive playgrounds** that run the real engine in the browser
  from a committed copy of its own zero-dependency bundle — no CDN, no
  npm install.
- **A use-cases guide**: four production architectures with diagrams,
  each assembled from shipped APIs.

## Security

Engine-side hardening (no posture regression; these close gaps):

- **CWE-789 memory amplification** — the pure inflater no longer
  allocates the (attacker-controlled) declared uncompressed size upfront;
  it grows toward the bound by doubling. A central directory claiming a
  1 GiB entry with a tiny payload can no longer force a 1 GiB allocation.
- **CWE-67 device names** — `sanitizeEntryPath`, the documented gate for
  external filesystem sinks, now rejects Windows reserved device names
  (`CON`, `NUL`, `COM1`…`LPT9`).
- **Corrupt-stream detection** — over-subscribed and incomplete Huffman
  tables are now rejected (zlib's Kraft check) instead of decoding to
  silent garbage through the public `createInflator`/`inflateRawJS`.
- **Silent-corruption guards** — oversized extra fields (u16 wrap) and
  Zip64 ≥ 4 GiB sizes in the incremental `save()` append path are caught
  at write time rather than emitting a corrupt archive.
- **Process robustness** — a throwing worker-pool main-thread fallback
  rejects the job instead of crashing the process and hanging
  `toBytes()`.

## Breaking Changes

None.

## Fixed

The 13 findings (A1–A6, B1–B7) are listed in
[CHANGELOG.md](../CHANGELOG.md#081---2026-09-01). Every message is
byte-identical to 0.8.0 except where a new typed refusal replaces a raw
error (`ZIP_DEFLATE_CORRUPT` for corrupt Huffman tables, `ZIP_INVALID_OPTION`
for an oversized extra field or an out-of-range per-entry level, and a
clean empty read where `readExact(0)` used to leak a `TypeError`).

## Added

- `docs/guides/use-cases.md` + four `use-case-*.svg` diagrams.
- `docs/playgrounds/` (toolkit, inspector, secure-extraction) + the
  `docs:playground` script and the `playground-bundle` verify-docs rule.

  names; guide pages carry the full site footer.

## Known limitations

Unchanged from 0.8.0 (store+bit3 / encrypted+bit3 forward reads;
Zip64 streaming for `addStream` > 4 GiB; zipnative.dev DNS).

## Downstream integration notes

The playground bundle demonstrates the browser path: it never calls
`initNodeZipCodecs()` (a Node-only optimisation). The playgrounds use
the synchronous APIs and therefore exercise the pure-TS tier
exclusively.
