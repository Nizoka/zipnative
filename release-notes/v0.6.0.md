# zipnative v0.6.0

<!-- GitHub Release title: v0.6.0 — resumable inflater & docs infrastructure -->

_Released 2026-09-01_

The resumable-inflater release — the 0.6 roadmap headline plus the first slice of the hardening band. A resumable pure-TS inflater lets `iterateZipEntries()` finally read data-descriptor (bit-3) archives forward, and the documentation gains its mechanical backbone: extracted `api.json`, the llms artefact pipeline, a zero-dependency docs site v1 and a ~15-rule verifier. **100% backward-compatible with v0.5.0** — `ZipUnsupportedError('cd-less-descriptor')` is now thrown for strictly fewer inputs (store/encrypted/custom-codec + bit 3 only); deterministic output bytes unchanged. Zero runtime dependencies. Tagged in git; not published to npm.

## Highlights

- **Forward reading of data-descriptor archives.** The new resumable pure-TS inflater reports exactly where a deflate stream ends, so `iterateZipEntries()` can now delimit bit-3 entries and validate their trailing descriptor against the *measured* CRC and sizes. zipnative's own `addStream()` output — and bsdtar-style producers — are forward-readable at last; our own interop fixture is the regression test.
- **A documentation stack agents can trust**: mechanical `api.json` (the export surface, extracted — never guessed), the llms artefact pipeline, a zero-dependency docs site v1, and a verifier grown to ~15 named rules that rebuild every generated artefact in memory and byte-compare.

## Security

- **feat(security):** descriptor identification is **validation-driven** — a form is accepted only when all three of its fields reproduce the measured values, so the classic "stored CRC happens to equal `PK\x07\x08`" collision cannot mislead the parser, and the adversarial worst case is a clean typed error at the next record — never trusted wrong content.
- **feat(security):** bit-3 entries have no declared sizes; their protection is output counting against `maxEntryUncompressedSize`/`maxTotalUncompressedSize` plus an incremental compression-ratio guard, stated in the TSDoc.
- **feat(security):** the forward reader's trust caveat is unchanged — local headers only; `openZip()` remains the authoritative path.

## Added

- **feat(codecs):** `createInflator()` (internal — deliberately not public API yet; the freeze phase decides its surface), `matchDataDescriptor()`, chunk-cursor `nextChunk`/`unread`/`peekUpTo`, raw-builder descriptor crafting for all four forms with attack overrides.
- **feat(docs):** `npm run docs:api`, `npm run docs:llms`, `npm run docs:all`; the `docs/` site (landing + quickstart/security/determinism guides + sitemap/robots/favicon); ~9 new verify-docs rules.

## Changed

- **docs(guides):** `docs/determinism.md` → `docs/guides/determinism.md`.
- **fix(parser):** the known-size fallback without `DecompressionStream` now streams via the resumable inflater (the buffer-whole-entry caveat is gone).

## Install

Not published to npm — pre-1.0 versions are git tags (`git checkout v0.6.0`); the first npm publication is v1.0.0.

## Upgrade

No breaking changes. Drop-in replacement for v0.5.0.

## Known limitations

- store+bit3, encrypted+bit3 and custom-codec+bit3 remain refused in forward reading — structurally undelimitable without the central directory.
- The docs site ships without an og:image PNG (rendering one is outside the zero-dependency local toolchain; deferred with the SVG source in place) and without the md→html guide renderer (guides are hand-paired; `data-md` anchors are in place so adopting the renderer later is purely additive).
- zipnative.dev is the intended domain; DNS/CNAME activation is a deployment step, not a repo artefact.

## Downstream integration notes

None (satellite packages do not exist yet). For the future CLI: forward streaming can now cover most real-world pipes; only store+bit3 producers need the seekable path.
