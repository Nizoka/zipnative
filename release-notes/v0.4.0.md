# zipnative v0.4.0

<!-- GitHub Release title: v0.4.0 — incremental modification -->

_Released 2026-09-01_

Milestone M3 — incremental modification. `createZipModifier()` brings the pdfnative incremental-update model to ZIP: replace, add, remove or rename entries and `save()` without recompressing the untouched 99%, with `saveCompact()` as the true-deletion path. **100% backward-compatible with v0.2.0** — `createZip` output bytes are unchanged (the determinism goldens prove the internal refactor is byte-neutral). Zero runtime dependencies. Tagged in git; not published to npm.

## Highlights

- **`createZipModifier()`** — replace, add, remove or rename entries of an existing archive and `save()` **without recompressing the untouched 99%**: the original bytes are copied verbatim and only the changes are appended (the pdfnative incremental-update model, applied to ZIP).
- **`saveCompact()`** — the true-deletion path: a canonical rewrite through the same byte-emission engine as `createZip`, still with zero recompression.
- **Contributor sample corpus** — `npm run test:generate` writes 22 self-validated demonstration archives to `test-output/`, including the `-original`/`-updated`/`-compacted` triple that shows append-only remanence vs true deletion in a hex editor.

## Security

- **feat(security):** data remanence, stated loudly — `removeEntry()` + `save()` does NOT erase content: the append-only layout keeps every original byte, and a `ZIP_DEAD_BYTES_RATIO` diagnostic fires when more than half the output is dead. `saveCompact()` is the deletion path. Pinned by tests that scan the output for the removed payload (found after `save()`, absent after `saveCompact()`).
- **feat(security):** the modifier never emits archives zipnative's own strict reader would flag — renames are raw copies (fresh local header, correct name), never re-pointed central-directory records.
- **feat(security):** duplicate-name source archives are refused with a typed `ZipFormatError` (name-keyed editing would be ambiguous).

## Added

- **feat(parser):** `createZipModifier` / `ZipModifier` / `ZipModifierOptions` (new "Modifying" export category).
- **feat(tests):** interop write cases `modified-incremental` and `modified-compacted` — foreign extractors accept and byte-compare incremental output, dead bytes included.
- **feat(samples):** `scripts/generate-samples.ts` + 8 generators + the `scripts/README.md` contributor guide; `verify:docs` sample-count canary.
- **feat(docs):** recipe `update-entry-in-place`.

## Changed

- **refactor(core):** `validateEntryName`/`compareNames` now live in `core/zip-encoding.ts` (shared by builder and modifier).

## Install

Not published to npm — pre-1.0 versions are git tags (`git checkout v0.4.0`); the first npm publication is v1.0.0.

## Upgrade

No breaking changes. Drop-in replacement for v0.2.0.

## Downstream integration notes

For the future `zipnative-cli`: `save()` output may legitimately contain an earlier EOCD inside the copied prefix — readers report it as the informational `ZIP_MULTIPLE_EOCD`; strict-mode consumers of incremental output should route diagnostics through `onDiagnostic`. `saveCompact()` drops SFX prefixes by design.
