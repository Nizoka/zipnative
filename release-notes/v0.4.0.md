# zipnative v0.4.0

Milestone **M3 — incremental modification**.

## Highlights

- `createZipModifier()`: replace, add, remove or rename entries of an
  existing archive and `save()` **without recompressing the untouched
  99%** — the original bytes are copied verbatim and only the changes are
  appended (the pdfnative incremental-update model, applied to ZIP).
- `saveCompact()`: the true-deletion path — a canonical rewrite through
  the same byte-emission engine as `createZip`, still with zero
  recompression.
- Contributor sample corpus: `npm run test:generate` writes 22
  self-validated demonstration archives to `test-output/`, including the
  `-original`/`-updated`/`-compacted` triple that shows append-only
  remanence vs true deletion in a hex editor.

## Security

- **Data remanence, stated loudly**: `removeEntry()` + `save()` does NOT
  erase content — the append-only layout keeps every original byte and a
  `ZIP_DEAD_BYTES_RATIO` diagnostic fires when more than half the output
  is dead. `saveCompact()` is the deletion path. Pinned by tests that
  scan the output for the removed payload (found after `save()`, absent
  after `saveCompact()`).
- The modifier never emits archives zipnative's own strict reader would
  flag: renames are raw copies (fresh local header, correct name), never
  re-pointed central-directory records.
- Duplicate-name source archives are refused with a typed
  `ZipFormatError` (name-keyed editing would be ambiguous).

## Breaking Changes

None. `createZip` output bytes are unchanged (the determinism goldens
prove the internal refactor is byte-neutral).

## Added

- `createZipModifier` / `ZipModifier` / `ZipModifierOptions` (new
  "Modifying" export category).
- Interop write cases `modified-incremental` and `modified-compacted` —
  foreign extractors accept and byte-compare incremental output, dead
  bytes included.
- `scripts/generate-samples.ts` + 8 generators + `scripts/README.md`
  contributor guide; `verify:docs` sample-count canary.
- Recipe `update-entry-in-place`.

## Changed

- `validateEntryName`/`compareNames` now live in `core/zip-encoding.ts`
  (shared by builder and modifier).

## Fixed

None.

## Downstream integration notes

For the future `zipnative-cli`: `save()` output may legitimately contain
an earlier EOCD inside the copied prefix — readers report it as the
informational `ZIP_MULTIPLE_EOCD`; strict-mode consumers of incremental
output should route diagnostics through `onDiagnostic`. `saveCompact()`
drops SFX prefixes by design.
