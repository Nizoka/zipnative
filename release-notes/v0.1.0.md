# zipnative v0.1.0

<!-- GitHub Release title: v0.1.0 — read engine & secure extraction -->

_Released 2026-09-01_

Milestone M1 — read, random access and secure extraction. The first release: a lazy central-directory reader with name-indexed random access, secure-by-default in-memory extraction, and Zip64 reading with anti-spoofing cross-checks, built on the full project scaffolding (strict TS, blocking Windows CI, CodeQL, Scorecard, interop conformance workflow, AI governance). Zero runtime dependencies. Tagged in git; not published to npm — versions identify code states, publication is distribution.

## Highlights

- **`openZip()`** — lazy central-directory reader with name-indexed random access: read one entry of a large archive without touching the rest.
- **Secure-by-default `extractZip()`** — zip-slip, symlink, duplicate-name and decompression-bomb guards, all CWE-tagged and caller-configurable.
- **Zip64 reading with anti-spoofing cross-checks** — ambiguous EOCD placement refused, overlapping entries rejected.

## Security

- **feat(security):** every untrusted-input loop is bounded by a named limit (`src/core/zip-limits.ts`), mirrored in SECURITY.md.
- **feat(security):** adversarial fuzzing suite built on an engine-independent raw byte-level archive builder (anti-circularity), including truncation/corruption rounds that assert clean typed errors — never hangs, never foreign exceptions.

## Added

- **feat(parser):** `openZip` / `ZipReader` (lazy `entries()`, `getEntry`, CRC-verified `readEntry`, `readEntryStream`, `readEntryRaw`, `verifyEntry`) and `extractZip` (in-memory, guards on by default).
- **feat(meta):** full project scaffolding — build, strict TS, lint, coverage thresholds, CI with a blocking Windows job, CodeQL, Scorecard, Dependabot, the interop conformance workflow, docs-integrity workflow, AI governance.
- **feat(tests):** foreign-provenance interop fixtures (PowerShell Compress-Archive, bsdtar) with a provenance ledger.
