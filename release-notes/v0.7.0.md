# zipnative v0.7.0

**Interop corpus expansion + docs finish** — the first slice of the
0.7→0.9 hardening band. No engine behavior changes in this release.

## Highlights

- **Guides are now machine-rendered.** `npm run docs:guides` renders every
  guide `.html` from its `.md` source (the `.md` is the single source of
  truth) with deep-linkable heading anchors from the same shared
  `slugify` the llms index uses — anchor parity by construction, verified
  by two new rules: `guide-render-sync` (in-memory rebuild must
  byte-match the committed shell) and `anchor-parity` (every internal
  fragment link must resolve). The pages stay prerendered-only: no
  client-side rendering code, no CDN scripts.
- **The interop write corpus grew from 7 to 11 cases (gate total: 17 validations with the 6 foreign-producer reads)**: SFX
  stub-prefixed archives (produced by the incremental modifier),
  comment-heavy archives, the bare empty archive, and store-only — each
  extracted and byte-compared by every available foreign tool.
- **The docs site got its finish coat**: a redesigned favicon and logo, a
  proper 1200×630 og:image on every page (the 0.6 deferral is closed),
  two inline architecture diagrams on the landing page, and
  `npm run docs:serve` for local preview.

## Security

- **Nothing new engine-side — deliberately.** This release ships no
  parser or writer behavior change; the security posture is unchanged
  from 0.6.0.
- What it does add is a **refusal-posture regression suite**: archives
  that many foreign extractors tolerate (multi-disk EOCDs in both the
  classic and zip64-locator forms, entries-on-disk counts contradicting
  the total, trailing garbage after the EOCD) are pinned to their typed
  refusals. The gap with tolerant tools is deliberate — silent
  tolerance is the parser-differential/smuggling surface this project
  rejects — and it is now tested, not just documented.
- The `sfx-prefixed` interop case documents a real third-party gap:
  .NET's `Expand-Archive` cannot extract stub-prefixed archives (it does
  not shift offsets for prepended data, on any platform); zipnative,
  bsdtar and 7-Zip all can.

## Breaking Changes

None.

## Added

- `scripts/build-guides.ts` (`docs:guides`, in `docs:all`; `marked`
  12.0.2 exact as a devDependency — build-time only, the runtime stays
  zero-dependency), verify-docs at ~17 named rules, `docs:serve`,
  CONTRIBUTING "Docs local preview".
- `docs/favicon.svg` redesign, `docs/assets/logo.svg`,
  `docs/assets/og-image.svg` + rendered `og-image.png`, og/twitter card
  metadata on all pages, `#architecture` landing section (two
  theme-aware inline SVG diagrams).
- Interop write cases `sfx-prefixed`, `comment-heavy`, `empty-archive`,
  `store-only`; platform-qualified `excludeTools` (`tool@platform`).
- `tests/integration/refusal-posture.test.ts`.

## Changed

- Inter-guide links in the `.md` sources target the paired `.html`
  pages (kept honest by `anchor-parity`).

## Fixed

None.

## Known limitations

- store+bit3, encrypted+bit3 and custom-codec+bit3 remain refused in
  forward reading — structurally undelimitable without the central
  directory.
- zipnative.dev is the intended domain; DNS/CNAME activation is a
  deployment step, not a repo artefact.

## Downstream integration notes

None (satellite packages do not exist yet). Guide anchors are now
stable, machine-generated identifiers — safe to deep-link from external
docs and agent prompts.
