The zipnative determinism contract

Reproducible output is a product feature with a written contract: what is guaranteed always, what is guaranteed per environment, and what compression: { deterministic: true } pins bit-for-bit on every runtime.

The three levels of guarantee

  1. Structurally deterministic — always. Entry order, header layout, flags, attributes, timestamps and Zip64 decisions never depend on the clock, randomness, locale or environment.
  2. Bitwise deterministic per environment — the default. Deflate compresses through the best available tier, so bytes are stable for a given runtime + zlib build.
  3. Bitwise deterministic everywhere — deterministic: true. The pure-TS encoder is pinned: SHA256(A) === SHA256(B) for identical inputs on every runtime — the mode for content addressing, reproducible builds, caching and signatures.

Canonicalization rules (always)

Entries sort by raw UTF-8 name bytes (order: 'insertion' preserves call order); timestamps default to the DOS epoch ('now' costs a diagnostic); version-made-by, external attributes and flags are constants; Zip64 records appear exactly when a field overflows; empty content is stored and deflate falls back to store when it does not shrink the payload — both pure functions of the content.

The frozen encoder contract

Under deterministic: true, every constant of the pure-TS encoder is frozen public API — the hash function, zlib's level configuration table, the one-step-lazy tie rules, the Huffman construction ordering and the block-cost tie order. Changing any of them changes emitted bytes and is a semver-major release; golden SHA-256 tables in the test suite are the tripwire.
